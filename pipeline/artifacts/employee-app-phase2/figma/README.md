## Fidelity pass (second run, 2026-10-26)

The first pass only matched structure. A side-by-side audit against the HTML
baselines (Playwright geometry + computed styles) found visual mismatches; all
were fixed in the plan compiler and rebuilt:

- **Buttons** now mirror the renderer's classes: `primary` (36h, radius 6,
  paddingX 16), `secondary`/`danger` carry borders (`border.control`,
  `status.danger` at 40% alpha), `ghost` is a transparent text button, and
  `ghost-chip` (32h, radius 8, paddingX 12, `border.strong`) is used for
  `.btn.ghost` inside `.filter-row`.
- **Dividers**: list rows and detail rows carry a 1px `border/subtle` bottom
  stroke, matching `.list-row` / `.list-text-row`.
- **Tab bar** uses page names (今日 / 预约列表) instead of raw ids, real
  Material Symbols glyphs (`home`, `calendar_month`), and a top-only border.
- **Inputs/selects** are 14px / 400 with radius 8 and `border.control`; the
  select shows its first option ("到店"), as a native `<select>` does.
- **Empty states** omit the icon unless the spec supplies one.
- **Calendar**: selected day uses a 600-weight label and a 2px info underline,
  its cells carry the 4% info tint, and blocks have a 2px tone-colored left
  border, 600-weight title and 10px subtitle/time. ABSOLUTE children now get
  explicit sizes, so headers/cells/blocks fill their columns.
- All 8 plans were regenerated; all 16 pages were rebuilt from scratch, and the
  16 diffs remain `0 blocker / 0 major / 0 findings`.

## Fixes found by the real gate
Plugin (`runtimes/figma/src/plugin.ts`):

1. `getMainComponent()` is rejected under `documentAccess: "dynamic-page"` → `getMainComponentAsync()`.
2. Instances were read back with their internal `Label` child → hierarchy blockers on every
   page with a Button (`expected 0 children, got 1`). Instances are now leaves; the label is
   still captured through `characters`.
3. Figma drops paint `opacity` when a paint is bound to a variable → tinted tokens
   (`fillAlpha < 1`) now use generated RGBA variables (`<token>/alpha-NN`), so badges and
   calendar blocks keep the HTML tint.

Plan compiler (`core/figma/src/compile-plan.ts`):

4. `MobileShell` only read `slots.content`; `detail`/`notice` archetypes put content in
   `summary`/`fields`, so customer-detail, appointment-detail and treatment-notice rendered
   empty frames. All content slots are now composed in renderer-html order
   (`title → illustration → body → summary → feed → fields → content`).
5. Search result rows (`ListRow` with `searchText`) are hidden until a query matches in the
   HTML; the default plan now skips them.
6. View-panel sections keep their vertical padding and drop horizontal padding, matching
   `[data-view-panel]` in the renderer.

Plugin UI (`runtimes/figma/src/ui.html`): build mode is a radio pair instead of a native
`<select>` (macOS NSMenu popups cannot be driven by the CUA bridge); scratch stays default.

## Repro

```bash
cd pipeline
# plans are checked in; to regenerate from the same specs:
pnpm figma:plan --spec-run artifacts/employee-app-phase2/figma/spec-source \
  --out artifacts/employee-app-phase2/figma/plans

# Serve plans + auto-save routes. Scratch readbacks go to readback/, delivery
# readbacks to readback/delivery/, and the exported PNG to parity/figma.<page>.png.
pnpm figma:serve --figma artifacts/employee-app-phase2/figma --port 9600
# Figma desktop: run runtimes/figma/manifest.json (Development → PRD UI Figma Renderer),
# load each plan from http://127.0.0.1:9600/plans/<file>, pick Build mode, Build.
pnpm figma:verify --plan artifacts/employee-app-phase2/figma/plans/figma-plan.<page>.json \
  --readback artifacts/employee-app-phase2/figma/readback/figma-readback.<page>.json \
  --out artifacts/employee-app-phase2/figma/diff/figma-diff.<page>.json
pnpm figma:parity --figma artifacts/employee-app-phase2/figma/parity \
  --baseline baselines/employee-app-phase2 \
  --spec-run artifacts/employee-app-phase2/figma/spec-source \
  --out artifacts/employee-app-phase2/figma/parity
```

`figma:serve` is the supported save route. A manual download/copy is a fallback
only: the delivery readback must be placed in `readback/delivery/` so it does not
overwrite the scratch readback.

## Caveats

- **The v0.7 regenerated plans invalidate this v0.6 evidence**: the card/quick-action/calendar/list style corrections mean the checked-in `readback/`, `diff/` and `screenshots/*` are stale. `figma:sign` re-derives each diff and refuses the stored `passed: true` flags until the 8 Figma pages are rebuilt and fresh readbacks are captured.
- The `screenshots/*` crops are v0.6 manual canvas captures, not parity evidence. A handoff package copies them only to `screenshots/figma-manual/` with a known-gap note; the primary `screenshots/figma/<page>.png` comes from `parity/figma.<page>.png`.
- Figma scratch pages are volatile: closing the tab before copying readbacks loses them.
- The registered development plugin points at `~/Downloads/prd-ui-figma/`; after
  `pnpm --dir runtimes/figma build`, copy `dist/{code.js,ui.html}` there or Figma runs the
  previous bundle.
- Delivery build refuses to overwrite an existing same-name page by design.
