# 员工端小程序 PRD（M1 切片摘要）

> 这是 M1 Agent 层的输入样本，只覆盖「今日」与「库存查询」两页。它不是完整 PRD，也不替代原文。

- 项目：`employee-app`
- 形态：微信小程序（uni-app），门店一线员工移动工作台
- 角色：`store_manager`（店长）、`beautician`（美容师）、`front_desk`（前台）、`warehouse`（库管）
- 平台：mobile

## 1. 范围

首版实现两个页面：

1. `今日`（`/today`）：查看当天预约与待回访，查询库存。
2. `库存查询`（`/inventory`）：搜索、筛选、查看本店产品当前库存、可用库存与预警。

不在首版范围：开单全流程、调拨、欠款还款、预约日历、客户详情、工作台、我的。M1 启用两个底部 Tab：`今日`、`库存查询`；`客户`、`工作台`、`我的` 在后续切片加入。两页对全部门店角色只读开放；库管登录后落地 `/inventory`。开单/预约的目标流程不在 M1，今日不提供这两个可点击动作。

## 2. 页面与权限

| 页面 | 路由 | 可见角色 | 必需状态 |
|---|---|---|---|
| 今日 | `/today` | store_manager, beautician, front_desk, warehouse | default, empty, loading, error |
| 库存查询 | `/inventory` | store_manager, warehouse, beautician, front_desk（只读） | default, empty, loading, error |

- 今日：顶栏显示门店名（不显示消息入口）；快捷操作「库存查询」；我的预约列表（客户、项目、时间、状态）；待回访列表。
- 库存查询：搜索、产品分类筛选、「仅看预警」开关；汇总行；产品卡片显示当前库存、可用库存、在途数量、低库存/缺货徽标。
- 库存查询是只读页面，M1 对全部门店角色开放，避免今日快捷入口出现无权限死路；库管仍以库存查询为落地页。
- 库管登录后落地库存查询；今日与库存查询均为底部 Tab。
- 无权限角色不显示入口；直接访问时展示无权限提示。

## 3. 主流程

```text
今日（查看预约）
  -> 点击「库存查询」快捷操作
  -> 库存查询（搜索/筛选）
  -> 返回今日

库管登录
  -> 库存查询（默认落地页）
```

今日是首页，也是预约和回访的入口。库存查询有底部 Tab，也保留今日快捷入口；今日不提供开单/预约动作。

## 4. 状态

- `default`：有预约/有产品，正常渲染。
- `loading`：骨架屏；提交类操作禁用。
- `empty`：今日无预约显示「今天没有预约」；库存无结果显示「没有匹配的产品」。
- `error`：显示错误说明与重试入口，保留筛选条件。
- 库存低库存、缺货使用状态徽标；徽标颜色由设计系统 token 决定，PRD 不指定色值。

## 5. 视觉与资产

- 品牌色、字体、图标风格尚未提供具体规范。
- 首版使用中性 B 端基线：黑/白/灰 + 语义色；Noto Sans SC。
- 标准 UI 图标优先使用面性图标库；空态插画首版使用占位或简单线性插画。
- 动效保持低强度，使用设计系统 motion token。

## 6. 待确认项

- 品牌主色与字体。
- 图标风格（面性 vs 线性）。
- 客户手机号展示口径（本切片不展示手机号，暂不阻塞）。
