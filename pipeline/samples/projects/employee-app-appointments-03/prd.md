# 员工端小程序 PRD（03 预约与告知 · 测试切片）

> 本文件是《03-预约与告知》的测试切片摘要，用真实 PRD 验证 PRD → UI 流水线；共享规则摘自《00-总纲》。它不是完整 PRD，也不替代原文。
> 源文件：`03-预约与告知.md`（§8 预约详情、§9 告知确认、§11 预约列表）；共享规则：`00-总纲.md`（§0.3–§0.9）。

- 项目：`employee-app-appointments-03`
- 形态：微信小程序（uni-app），门店一线员工移动工作台
- 平台：mobile
- 角色：`store_manager`（店长）、`beautician`（美容师）、`front_desk`（前台）、`warehouse`（库管）

## 1. 业务范围

本切片覆盖员工端的四页：预约详情、新增/改期预约、术后告知、预约列表。员工在服务现场完成预约到店确认、改期、取消、开单入口、术后告知确认，以及按日历/列表查看预约。

范围内：

- 预约详情：查看客户、项目、时间段、护理师、门店、来源、创建人与创建时间；按状态提供到店确认、开单、改期、取消。
- 新增/改期预约：新增预约与改期复用同一表单页；改期时客户锁定，项目、时间段、护理师、来源可改。
- 术后告知：按项目分块展示告知话术，员工当面告知客户后确认；确认后只读。
- 预约列表：我的排单 / 全店两个视角，日历 / 列表两个维度；状态高亮或筛选；新增预约。

不在范围内：

- 开单三步流程本身（见《05-开单与单据》§16），本切片只提供开单入口。
- 客户详情、回访、库存、调拨、欠款还款、个人业绩、消息与公告。
- Web 专属操作：整单作废、冲正、盘点、退卡、催收登记、客户档案编辑。
- 爽约入口：员工端不提供爽约操作，爽约状态只读可见。

## 2. 角色与权限

员工端功能由门店在后台按人勾选；缺权时入口不出现，只读档位下写操作置灰并由系统拦截。

| 功能点 | 说明 | 本切片相关动作 |
|---|---|---|
| 预约登记 | 预约新增、改期、取消、改派 | 新增预约、保存改期、取消 |
| 到院分配 | 排单行标记已到店 | 已到店确认、接单并确认到店 |
| 开单 | 进入开单流程 | 预约详情「开单」入口 |
| 术后告知 | 服务完成确认与告知确认 | 确认已当面告知 |

只读档位：门店被设为只读时，所有写操作（到店确认、接单、开单入口、新增、保存改期、取消、确认告知）置灰并由系统拦截；读操作正常。只读不是独立角色，也不改变页面可见性。

| 页面 | 可见角色 | 说明 |
|---|---|---|
| 预约详情 | store_manager, beautician, front_desk, warehouse | 需预约登记或到院分配功能点；库管仅勾选到院分配时也可查看，避免有详情无列表的死角 |
| 新增/改期预约 | store_manager, beautician, front_desk, warehouse | 需预约登记功能点；只读档位下只读查看或入口不出现 |
| 术后告知 | store_manager, beautician, front_desk, warehouse | 需术后告知功能点 |
| 预约列表 | store_manager, beautician, front_desk, warehouse | 需预约登记或到院分配功能点；与预约详情同一可见条件 |

数据范围与视角：

| 视角 | 可见条件 | 内容 |
|---|---|---|
| 我的排单 | 可访问预约列表的角色 | 派给我与今日有效委派的单；可含跨店行并显示门店名 |
| 全店 | 拥有预约登记或到院分配功能点 | 当前门店全部预约；store_manager 与 front_desk 默认具备，beautician 默认具备预约登记，warehouse 仅在勾选任一项时可见 |

客户手机号在员工端一律脱敏，不提供完整号与拨号。

## 3. 页面清单

| 页面 | id | 路由 | 形态 | 核心内容 | 必需状态 |
|---|---|---|---|---|---|
| 预约详情 | `appointment-detail` | `/appointments/:id` | 移动端详情页，底部固定操作栏 | 客户、状态、脱敏手机号、项目、时间段、护理师、门店、来源、创建人、创建时间、委派留痕 | default, loading, error, disabled |
| 新增/改期预约 | `appointment-form` | `/appointments/new` | 移动端表单页；改期使用同一页的 mode=改期 | 客户（改期锁定）、项目、开始时间、结束时间、护理师、来源；保存 / 保存改期 | default, loading, error, disabled |
| 术后告知 | `treatment-notice` | `/notices/:id` | 移动端只读确认页 | 客户、单号、状态、按项目分块的告知话术、确认人、确认时间 | default, loading, error, disabled |

## 4. 状态矩阵

### 4.1 页面状态

| 页面 | default | empty | loading | error | disabled |
|---|---|---|---|---|---|
| 预约详情 | 有预约数据 | 不适用（单条详情） | 骨架屏 | 错误说明与重试 | 只读档位：写操作置灰 |
| 新增/改期预约 | 可编辑表单 | 不适用（表单页） | 骨架屏 | 错误说明与重试 | 只读档位：表单只读 |
| 术后告知 | 有告知数据 | 不适用（单条告知） | 骨架屏 | 错误说明与重试 | 只读档位：确认按钮置灰 |
| 预约列表 | 有预约 | 当前条件无预约，显示空态与清空筛选 | 骨架屏 | 错误说明与重试，保留筛选 | 不适用（列表只读） |

### 4.2 预约业务状态与动作

| 业务状态 | 预约详情动作 | 说明 |
|---|---|---|
| 已登记 | 已到店确认、开单、改期、取消 | 待分配时「已到店确认」文案为「接单并确认到店」，一次点击完成到店与接单 |
| 已到店 | 开单 | 底部只保留开单 |
| 爽约 | 无 | 只读说明：爽约已记录入客户档案 |
| 已取消 | 无 | 只读说明：本单已取消 |

状态机由系统硬校验：只有「已登记」可到店、改期、取消；非「已登记」动作会被拦截。员工端不提供爽约入口。

### 4.3 告知状态

| 业务状态 | 页面表现 | 允许动作 |
|---|---|---|
| 未确认 | 展示话术与确认按钮 | 确认已当面告知 |
| 已确认 | 只读，显示确认人与确认时间 | 无 |

### 4.4 预约列表状态选择

- 状态选项：全部、已登记、已到店、爽约、已取消。
- 日历维度用高亮：匹配块高亮、其余变淡，网格恒含全部状态。
- 列表维度用筛选：只显示匹配行。

### 4.5 新增/改期表单

| 项 | 规则 |
|---|---|
| 新增 | 客户必填，复用客户搜索；项目必填；时间段必填；护理师可选默认自己；来源必填默认到店 |
| 改期 | 客户锁定不可改；项目、时间段、护理师、来源可改；按钮文案「保存改期」 |
| 校验 | 开始时间必须早于结束时间；缺少必填项时阻止提交并提示 |
| 保存成功 | 回到预约详情；改期成功后详情显示新的时间段与护理师 |
| 取消 | 取消操作在预约详情触发，二次确认后状态变为已取消并回到详情只读说明 |
| 改派 | 不设独立改派按钮；改派 = 改期表单修改护理师；保存后详情显示「已改派给 X」留痕，系统处理当日委派撤旧授新 |

## 6. 验收示例

1. 预约详情（已登记）：张女士，138****0000，小气泡，11-05 周三 10:00-11:00，王美容（我），星光店，来源电话，创建人李前台；底部显示「已到店确认」「开单」「改期」「取消」。
2. 预约详情（已到店）：同一单到店后，底部只剩「开单」；改期与取消不出现。
3. 预约详情（爽约/已取消）：底部操作栏不出现，显示只读说明「爽约已记录入客户档案」或「本单已取消」。
4. 预约详情（待分配）：护理师显示「待分配」，主按钮文案为「接单并确认到店」；点击后状态变为已到店并接单。
5. 术后告知（未确认）：单号 SO20261102001，话术按小气泡、补水两个项目分块；点击「已当面告知客户，确认」后变为已确认并显示确认人与确认时间。
6. 术后告知（已确认）：按钮消失，页面只读；重新进入页面时话术内容与确认时一致，不依赖后台改话术即可观察快照冻结。
7. 预约列表（日历）：默认周一至周日七列网格，块高等于时长，今天列高亮；状态选择「已登记」时匹配块高亮、其余变淡；点空格进入新增预约并预填日期时间；点已有块进入预约详情。
8. 预约列表（列表）：按日期分组连续滚动；行一显示时间段、客户名、状态徽标与箭头；行二显示项目；全店视角追加护理师；状态选择「已登记」时只显示已登记行。
9. 新增预约：客户必填，复用客户搜索；项目必填；时间段必填且开始早于结束；护理师可选默认自己；来源必填默认到店；保存后回到预约详情。
10. 改期：从预约详情点「改期」进入同一表单，客户锁定；修改时间段或护理师后按钮为「保存改期」；保存后详情显示新的时间段与护理师。
11. 改派：改期表单把护理师从王美容改为赵××并保存；详情护理师显示赵××，并出现「已改派给 赵××」留痕；不出现独立改派按钮。
12. 取消：预约详情点「取消」出现二次确认；确认后状态变为已取消，底部操作栏消失，显示「本单已取消」。
13. 只读档位：门店设为只读时，到店确认、新增、保存改期、取消、确认告知全部置灰并被系统拦截；列表与详情仍可读。
14. 手机号：以上所有页面与动作回显的客户手机号一律脱敏，不出现完整号与拨号入口。

## 7. 主流程

1. 首页「我的预约」行 → 预约详情 → 已到店确认 / 开单 / 改期 / 取消。
2. 预约详情 → 改期 → 新增/改期预约（mode=改期）→ 保存改期 → 预约详情。
3. 预约列表底部「新增预约」或日历点空格 → 新增/改期预约 → 保存 → 预约详情。
4. 服务完成 → 自动生成术后告知 → 术后告知页 → 已当面告知客户，确认。
5. 首页「我的预约」卡头或工作台「客户预约」→ 预约列表 → 日历或列表 → 点空格新增 / 点块或行进入详情。

## 8. 导航

底部四个 Tab：今日、客户、工作台、我的。

- 预约详情是二级页，从首页「我的预约」行、预约列表行、日历块进入；页头左端返回，底部固定操作栏。
- 新增/改期预约是二级页，从预约列表底部「新增预约」、日历空格、预约详情「改期」进入；页头左端返回；保存后回到预约详情。
- 术后告知是二级页，从服务完成流程或客户详情服务记录行进入；页头左端返回。
- 预约列表是二级页，从首页「我的预约」卡头或工作台进入；页头左端返回；主操作「新增预约」固定在底部拇指区。

本切片只交付 03 的四页。以下宿主页面属于其他分册，不作为本切片的页面清单，也不在本切片验收：

- 客户详情（《02-客户》）服务记录行提供术后告知兜底入口。

## 10. 共享规则

- 空态、筛选无结果、条件开关无结果、加载失败必须区分；加载失败显示错误态与重试，不显示成空态。
- 首屏骨架屏；下拉刷新不遮罩已有内容；写操作不自动重试，失败不丢已填。
- 无功能点入口不出现；只读档位写操作置灰并拦截；登录失效全局跳登录并记住回跳目标。
- 列表默认时间倒序；下拉刷新与上拉加载；到底显示「没有更多」。
- 客户手机号在员工端一律脱敏；不提供完整号、拨号或申请授权入口。
- 枚举与字段名沿用系统叫法；员工端不新增或改写枚举。
- 预约与订单没有关联字段：预约详情不显示开单状态，重复开单的拦阻落在开单页。
- 新增/改期表单：开始时间必须早于结束时间；必填项缺失时阻止提交并提示；失败保留已填内容。

## 11. 首版决策

- 状态文案沿用系统枚举（已登记 / 已到店 / 爽约 / 已取消；未确认 / 已确认）；口语化命名后续统一，不阻塞首版。
- 新增预约来源默认「到店」；快速建档不在本切片，搜不到客户时引导到客户 Tab 新建。
- 新增与改期共用 `appointment-form`，以 mode 区分；改期时客户锁定。
- 只读档位是门店级开关，不是独立角色；只影响写操作，不改变页面可见性。
- 不设独立改派按钮；改派 = 改期表单修改护理师，详情只显示留痕。
- 日历与列表两个维度首版都保留；日历为七列网格，列表为按日期分组。
- 开单动作进入《05-开单与单据》§16 的三步流程，本切片只提供入口。
- 列表维度状态用筛选，日历维度状态用高亮；两者信息等价。
