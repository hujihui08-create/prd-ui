# 员工端小程序 PRD（Phase 2 出口 · 8 页真实切片）

> 本文件从员工端 PRD 十册的《00-总纲》《01-首页与工作台》《02-客户》《03-预约与告知》《04-回访》抽取 8 页，作为 Phase 2 出口的真实 PRD 测试输入；原始 Markdown 不修改。共享规则以《00-总纲》为准。

- 项目：`employee-app-phase2`
- 形态：微信小程序（uni-app），门店一线员工移动工作台
- 平台：mobile
- 角色：`store_manager`（店长）、`beautician`（美容师）、`front_desk`（前台）、`warehouse`（库管）

## 1. 业务范围

本切片覆盖员工端 8 页：今日、客户搜索、客户详情、预约详情、新增/改期预约、术后告知、预约列表、回访登记。员工在服务现场完成接待、查客户、确认到店、改期/取消、术后告知和回访登记。

范围内：

- 今日：查看当天预约与待回访，进入开单、预约。
- 客户搜索/详情：按姓名或手机号搜索客户，查看客户基础信息、卡项与消费摘要。
- 预约：详情、到店确认、改期、取消、新增、日历/列表双维度、术后告知。
- 回访：登记回访内容与结果。

不在范围内：

- 开单三步流程、订单详情、收款与签字（见《05-开单与单据》）。
- 库存入库/出库/调拨、欠款还款、个人业绩、我的、消息与公告。
- Web 专属操作：整单作废、冲正、盘点、退卡、催收登记、客户档案编辑。
- 爽约入口：员工端不提供爽约操作，爽约状态只读可见。
- 客户 Tab 的默认客户列表：客户搜索页只做搜索与新建入口。

## 2. 角色与权限

门店在后台按人勾选员工端功能；缺权时入口不出现，只读档位下写操作置灰并由系统拦截。

| 功能点 | 说明 | 本切片相关动作 |
|---|---|---|
| 预约登记 | 预约新增、改期、取消、改派 | 新增预约、保存改期、取消 |
| 到院分配 | 排单行标记已到店 | 已到店确认、接单并确认到店 |
| 开单 | 进入开单流程 | 今日快捷操作、预约详情开单入口 |
| 术后告知 | 服务完成确认与告知确认 | 确认已当面告知 |
| 回访登记 | 记录回访 | 保存回访 |
| 客户查看 | 搜索与查看客户详情 | 搜索、查看详情、查看告知 |

本切片不包含：客户建档、库存查询、入库、出库；相关入口由宿主页面提供，不在 8 页内。库管如需在新增预约中选择客户，必须同时具备客户查看功能点。

只读档位：门店被设为只读时，所有写操作（到店确认、接单、开单入口、新增、保存改期、取消、确认告知、保存回访）置灰并由系统拦截；读操作正常。只读不是独立角色，也不改变页面可见性。

| 页面 | 可见角色 | 说明 |
|---|---|---|
| 今日 | store_manager, beautician, front_desk | 库管不进入今日；库存查询等入口由宿主提供 |
| 客户搜索 | store_manager, beautician, front_desk, warehouse | 需客户查看；库管仅在勾选客户查看时可见 |
| 客户详情 | store_manager, beautician, front_desk, warehouse | 店长/前台可见本店客户；美容师为服务过 ∪ 当日有效委派；库管为当日有效委派 |
| 预约详情 | store_manager, beautician, front_desk, warehouse | 需预约登记或到院分配 |
| 新增/改期预约 | store_manager, beautician, front_desk, warehouse | 需预约登记 |
| 术后告知 | store_manager, beautician, front_desk, warehouse | 需术后告知 |
| 预约列表 | store_manager, beautician, front_desk, warehouse | 需预约登记或到院分配 |
| 回访登记 | store_manager, beautician, front_desk | 需回访登记 |

数据范围：

| 视角 | 可见条件 | 内容 |
|---|---|---|
| 我的排单 | 可访问预约列表的角色 | 派给我与今日有效委派的单；可含跨店行并显示门店名 |
| 全店 | 拥有预约登记或到院分配功能点 | 当前门店全部预约；store_manager 与 front_desk 默认具备，beautician 默认具备预约登记，warehouse 仅在勾选任一项时可见 |

客户手机号在员工端一律脱敏，不提供完整号与拨号。

客户可见性定义：

| 概念 | 定义 |
|---|---|
| 服务过 | 当前员工有该客户的服务记录 |
| 当日有效委派 | 今日预约的护理师或原护理师是当前员工，且状态为已登记或已到店 |
| 可查看客户 | store_manager / front_desk 可见本店客户；beautician 为服务过 ∪ 当日有效委派；warehouse 为当日有效委派 |

客户搜索只返回可查看客户；不可查看客户不进入结果。验收：库管有当日委派时可搜索并打开该客户；美容师对未服务且无委派的客户搜索不到。

动作级权限：

| 动作 | 需要功能点 |
|---|---|
| 到店确认 / 接单并确认到店 | 到院分配 |
| 开单 | 开单 |
| 改期 / 取消 / 新增预约 | 预约登记 |
| 查看告知 | 术后告知，且可查看对应预约 |
| 回访登记 | 回访登记 |
| 客户详情·查看预约 | 预约登记或到院分配 |
| 客户详情·新增预约 | 预约登记 + 客户查看 |
| 客户详情·查看告知 | 术后告知 |
| 客户详情·回访登记 | 回访登记 |
| 新增预约（列表/日历/今日） | 预约登记 + 客户查看 |

无权限动作不出现；只读档位下仍可见但置灰。预约详情的客户详情入口仅在可查看该客户时显示链接，否则只显示客户姓名文本，不提供穿透。

## 4. 状态矩阵

### 4.1 页面状态

| 页面 | default | empty | loading | error | disabled |
|---|---|---|---|---|---|
| 今日 | 有预约/回访 | 无预约或无回访时显示对应空态 | 骨架屏 | 错误说明与重试 | 只读档位：开单/预约快捷操作置灰 |
| 客户搜索 | 有搜索结果；首次进入未输入关键词时显示搜索提示 | 无匹配客户，显示清空关键词 | 骨架屏 | 错误说明与重试，保留关键词 | 不适用 |
| 客户详情 | 有客户数据 | 不适用（单条详情） | 骨架屏 | 错误说明与重试 | 只读档位：新增预约/回访登记置灰 |
| 预约详情 | 有预约数据 | 不适用（单条详情） | 骨架屏 | 错误说明与重试 | 只读档位：写操作置灰 |
| 新增/改期预约 | 可编辑表单 | 不适用（表单页） | 骨架屏 | 错误说明与重试 | 只读档位：表单只读 |
| 术后告知 | 有告知数据 | 不适用（单条告知） | 骨架屏 | 错误说明与重试 | 只读档位：确认按钮置灰 |
| 预约列表 | 有预约 | 当前条件无预约，显示清空筛选 | 骨架屏 | 错误说明与重试，保留筛选 | 只读档位：新增预约置灰 |
| 回访登记 | 可编辑表单 | 不适用（表单页） | 骨架屏 | 错误说明与重试 | 只读档位：表单只读 |

### 4.2 预约业务状态与动作

| 业务状态 | 预约详情动作 | 说明 |
|---|---|---|
| 已登记 | 已到店确认、开单、改期、取消 | 待分配时「已到店确认」文案为「接单并确认到店」 |
| 已到店 | 开单；serviceCompleted=true 时显示术后告知 | 底部保留开单；服务完成后可进入术后告知 |
| 爽约 | 无 | 只读说明：爽约已记录入客户档案 |
| 已取消 | 无 | 只读说明：本单已取消 |

状态机由系统硬校验：只有「已登记」可到店、改期、取消；员工端不提供爽约入口。

### 4.3 告知状态

| 业务状态 | 页面表现 | 允许动作 |
|---|---|---|
| 未确认 | 展示分块话术与确认按钮 | 确认已当面告知 |
| 已确认 | 只读，显示确认人与确认时间 | 无 |

### 4.4 预约列表状态选择

- 状态选项：全部、已登记、已到店、爽约、已取消。
- 日历维度用高亮：匹配块高亮、其余变淡，网格恒含全部状态。
- 列表维度用筛选：只显示匹配行。

### 4.5 回访登记

| 项 | 规则 |
|---|---|
| 客户 | 必填，从今日待回访区块或客户详情带入 |
| 服务项目 | 必填，记录本单主服务项目（单个） |
| 回访内容 | 必填，记录客户反馈与下一步安排 |
| 回访结果 | 必填，已联系 / 未接 / 拒绝 / 稍后再联系 |
| 结果分支 | 未接 / 拒绝 / 稍后再联系保存后仍留在今日待回访区块，直到产生已联系结果或下次回访 |
| 保存 | 成功后回到今日待回访区块；从客户详情进入时回到客户详情；失败保留已填内容 |

## 6. 验收示例

1. 今日：星光店，快捷操作「开单」「预约」「客户搜索」；我的预约 3 条（张女士·小气泡·10:00-11:00·已登记；李女士·补水·14:00-15:00·已到店；王女士·肩颈·16:30-17:30·已登记）；待回访 2 条。

## 7. 主流程

1. 今日 → 我的预约行 → 预约详情 → 到店确认 / 开单 / 改期 / 取消。
2. 今日 → 待回访 → 回访登记 → 保存回访。
3. 客户搜索 → 客户详情 → 预约详情 / 新增预约。
4. 预约详情 → 改期 → 新增/改期预约（改期模式）→ 保存改期 → 预约详情。
5. 预约列表 → 日历/列表 → 点空格新增 / 点块或行进入详情。
6. 服务完成 → 术后告知 → 确认已当面告知。

## 10. 首版决策

- 状态文案沿用系统枚举：已登记 / 已到店 / 爽约 / 已取消；未确认 / 已确认。
- 新增预约来源默认「到店」；快速建档不在本切片，搜不到客户时引导到客户 Tab 新建。
- 新增与改期共用 `appointment-form`，以 mode 区分；改期时客户锁定。
- 只读档位是门店级开关，不是独立角色；只影响写操作。
- 不设独立改派按钮；改派 = 改期表单修改护理师，详情只显示留痕。
- 日历与列表两个维度首版都保留；日历为七列网格，列表为按日期分组。
- 术后告知按项目分块，快照冻结；确认后只读。
- 客户搜索接受姓名或脱敏手机号，不接受完整手机号；输入 11 位连续数字时提示仅支持姓名/脱敏号。本切片只返回可查看客户，全连锁查重由宿主提供。
- 新增预约从列表/日历进入时打开客户搜索选择器；从客户详情进入时预填客户并锁定。
- 预约列表默认日历维度，列表维度通过切换进入；日期筛选默认今天。
- 回访保存后回到今日待回访区块；从客户详情进入时回到客户详情。回访只记录单个主服务项目。
- 术后告知 noticeBlocks 非空时优先，空时回退 notices。告知路由使用 appointment id：`/appointments/detail/:id/notice`。
- 今日不面向库管；库管使用预约页与宿主库存入口。
- 预约与订单没有关联字段：预约详情不显示开单状态。
