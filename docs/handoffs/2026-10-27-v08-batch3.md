## 2. 代码改动

### 位置解析

- 新增 `core/compiler/src/action-placement.ts`：
  `resolveActionPlacements(actions)` → `{ footer, cardActions, overflow, inline }`。
  - 显式 `placement` 优先，且不占级联槽位；
  - 未显式时：第 1 个 footer、其后 3 个 card-actions、其余 overflow；
  - 显式 footer 会抑制位置级联的 footer，便于只标记主操作；
  - >1 footer 或 >3 card-actions 抛 `ACTION_PLACEMENT_CONFLICT`。
- `detailLayout` 按分组落位：
  - footer 进 `actions` 槽；
  - card-actions 进 `summary` 槽的 `Row{variant:"card-actions"}`；
  - overflow 生成 `ActionMenu`，排在 footer 之后；
  - `inline` 只在显式声明时保留 filter-row。
- 业务过滤保留：check-in/accept 去重（保留 primary）、`treatment.notice.view`
  仅在服务完成后出现、`appointment.cancel` 排最后且 danger。

### ActionMenu（五处联动）

| 层 | 改动 |
|---|---|
| contracts | `FigmaPlanNode.visible?: boolean`；readback 增加 `visible` |
| catalog | 三个 profile 都新增 `ActionMenu` 组件，`actions` 槽允许它；archetype `detail` 允许它 |
| renderer | `ActionMenu` 分支 + `.card-actions-row` / `.action-sheet` CSS + 交互 JS（点击、Esc、遮罩、焦点陷阱、`aria-expanded`） |
| plan | 触发器 instance + `visible:false` 的 `ActionSheet` frame；`Row{variant:"card-actions"}` 的 ghost 用 chip 变体 |
| plugin | FRAME 支持 `visible:false`；readback 导出 `visible`；`figma:verify` 对可见性不一致给 `FIGMA_VISIBILITY` |
| conformance | `visible:false` 的 plan 节点跳过；coverage 把菜单子项标 `SKIPPED_MENU_HIDDEN` |
