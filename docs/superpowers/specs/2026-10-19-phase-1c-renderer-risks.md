# Phase 1C · 高保真 Renderer 与交付包 · 风险登记

- 日期：2026-10-19
- 状态：待用户审阅
- 关联设计：`docs/superpowers/specs/2026-10-19-prd-to-ui-pipeline-design.md`（§15 已有总风险表；本文是对 B 方案、即 Phase 1C 的细化）
- 关联调研：`docs/superpowers/specs/2026-10-19-ai-asset-generation-research.md`（AI 资产专项风险 AI-01..AI-14）
- 范围：把最终产物定义为 **高保真 Figma 设计图 + 高保真 HTML 动效原型 + 1–2 张海报 + 切图/交付包**，并由同一份 Page Spec / RenderPlan 驱动。

## 0. 结论摘要

- **最大风险不是“写不出代码”，而是“视觉基准不唯一”和“设计系统输入不足”。** 如果 Figma 和 HTML 谁对谁错没有定义，两个 renderer 一定会漂移；如果没有真实设计系统/tokens，所谓“高保真”只能做到基线风格，不可能是品牌级设计图。
- **不建议承诺“像素级 100% 一致”。** 建议承诺“同一 RenderPlan 驱动 + 运行时结构断言 + 截图感知 diff 在阈值内 + 人工签核”，并把不可控差异（字体渲染等）写进豁免。
- **三条红线**：不允许无设计系统输入却宣称品牌级高保真；不允许跳过切图/资产校验交付；不允许 Figma 手动改稿后不回写 Page Spec。

### 已确认决策（2026-10-19）

1. 设计系统：先基线（`b-dense` / `c-expressive`）后接入真实系统。
2. 页面范围：8 页 sample + 真实切片（真实 PRD/内容待提供）。
3. 冲突优先级：`RenderPlan`/tokens 是契约；Figma 管静态视觉，HTML 管行为/动效；冲突只改契约，不单端手改。
4. 视觉验收：runtime 断言 + 截图感知 diff + 人工签核；waiver 必须有 owner/理由/有效期。
5. 动效：标准预设库（页面转场、列表 stagger、卡片 hover、按钮 press、输入 focus、骨架 shimmer、空态淡入、弹层/抽屉）。
6. AI 资产：标准 UI 图标走图标库；自定义图标允许 AI 原生矢量草稿；插画/海报图像层允许 AI；文字/logo/产品截图用确定性图层。
7. AI 工具：先小样本评测 Recraft vs Adobe Firefly，再定。
8. AI 风格参考：现有基线 + sample 页面。
9. AI 审校：用户/设计负责人签核。
10. 海报：首版交付 1–2 张。
11. 内容：按“内容细化”处理（真实业务数据、各状态文案、无 lorem ipsum）。

### 仍需确认

- 真实切片的 PRD、页面清单、内容/状态/权限。
- AI 工具评测结果与采购/授权。
- 海报主题、尺寸、是否印刷（CMYK/出血）。
- “内容细化”的字段级样例与业务词表。

## 1. 评级方法

- **概率**：低 / 中 / 高。
- **影响**：低 / 中 / 高。
- **等级**：P0（不解决不能开工）/ P1（进入对应 Phase 前必须关闭）/ P2（持续监控，不阻塞）。
- 每条风险必须有：可执行的缓解动作、可观察的触发信号、降级方案。

## 3. Top 5 风险（按处理优先级）

1. **R1 视觉基准二义性（P0）**——这是本轮“看起来不完美”的根因。必须先定“plan/tokens 是契约，HTML 管行为/动效，Figma 管静态设计/交付”。
2. **R2 设计系统输入不足（P0）**——决定“高保真”的上限。没有真实设计系统，只能交付基线风格；必须在开工前确认。
3. **R23 缺移动 B 端 profile（P0）**——真实 PRD 是员工端小程序（移动 B 端），现有 b-dense 是 Web、c-expressive 是移动 C 端；不先建 `b-mobile`，真实切片无法编译/风格不对。
4. **R24 PRD 视觉未定/口径冲突（P0/P1）**——颜色/字体/图标/组件视觉未给，客户手机号规则有冲突；必须先裁决，只选已定稿页面。
5. **R10 范围/周期（P0）**——B 是多阶段项目；真实 PRD 有 23 页，首版只做 `今日` + `库存查询`，不能铺全量；海报 1–2 张后置。

补充监控：R20（海报）、R19+R5（AI 图标/内容）、R3/R6（渲染差异/动效）、R4（Figma 桥接）、R8（视觉门禁）、R22（AI 审校）、R25（面性图标）。

## 4. 分阶段门禁与风险关闭

### 1C.1 · RenderPlan + 设计系统扩容 + 内容 + HTML/动效 + AI 工具评测

退出标准：
- 首版页面矩阵（默认现有 8 页；若改用真实 PRD 则按确认后的 6–8 页）能生成 RenderPlan；
- 每页有 default/empty/loading/error；
- HTML 原型可打开、可导航、有 motion spec 中的预览动效；
- 每页有细化后的真实示例内容（无 lorem ipsum/“示例 1”）；
- AI 工具评测完成：固定 8 个标准风格图标 + 2 个品牌图标 + 1 张中文海报 brief，对比 Recraft vs Firefly，输出可编辑性/一致性/网格/文字/授权评分与建议；
- 截图基线生成。

关闭/降级：R2（明确基线 or 真实系统）、R5/R21（content 模型）、R6（motion 清单）、R10（第一段交付）、R12（brief 内容要求）、R19（AI 图标准入规则）、R20（海报准入规则）、R22（审校流程）。

### 1C.2 · Figma Renderer

退出标准：
- Foundations + Components + 每页各状态 Frame 生成；
- 变量/文本样式/组件实例/资产填充正确；
- AI 评测通过的自定义图标以冻结 SVG 进入组件/页面；
- Figma runtime JSON 回读通过结构断言；
- 能导出页面 PNG + 资产切图；
- 已知偏差清单明确。

## 5. 降级策略（必须提前接受）

- **Figma 自动化失败**：交付 `figma-plan + 操作说明`，HTML 与切图仍交付；不阻塞整体，但 Figma 部分标记 degraded。
- **设计系统输入不足**：用基线 + 明确“非品牌最终稿”标注；不宣称 brand-ready。
- **视觉 diff 无法收敛**：结构断言 + 人工签核 + waiver；不无限追像素。
- **动效超范围**：退回 motion preset 清单；只演示清单内动效。

- **内容质量不足**：fixture + 人工审样；不交付 lorem ipsum。
- **桥接/插件不可用**：人工导入 Figma 插件 + 记录 commit/version；不伪造截图。
