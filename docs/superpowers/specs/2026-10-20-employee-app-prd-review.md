## 0. 结论

1. **PRD 质量很高，适合做真实切片。** 它覆盖范围、页面、权限、字段、状态、异常、列表规范、字号/间距/圆角，内容示例也足够，能直接抽取 UI Brief / Page Spec。
2. **它不是视觉设计稿。** 颜色（具体色值）、字体家族、图标风格、组件外观、动效、插画都未定；这些正是我们要用设计系统 + 高保真设计补上的部分。
3. **最大的架构缺口：它是移动端 B 端员工小程序，而现有 `b-dense` 是 Web B 端、`c-expressive` 是移动 C 端。** `b-dense` catalog 没有 `MobileShell`，直接编译 mobile 页面会失败。必须先做 **`b-mobile`**（移动 B 端 profile/catalog）。
4. **建议首版真实切片：`今日`（首页）+ `库存查询`（列表）两页。** 这两页覆盖 TabBar、顶栏、卡片、列表、筛选、搜索、徽标、数值块、空/错/加载态，且核心规则已定稿；`客户详情` 作为第三页。`开单`/`调拨`/`欠款` 暂不进首版。
5. **必须先确认**：品牌色/色值、字体、图标风格、目标视口（375×812 vs 390×844）、客户手机号口径（PRD 内部有冲突）、以及是否只用 PRD 示例内容。

## 1. PRD 概况

- 形态：微信小程序（uni-app），员工端移动工作台。
- 用户：门店一线全员（美容师/店长/库管/前台）；功能按人勾选，同一套端。
- 导航：底部四 Tab——`今日`、`客户`、`工作台`、`我的`。
- 规模：10 个文件、约 23 个页面/流程；核心模块：首页/工作台、客户、预约与告知、回访、开单与单据、欠款还款、库存、调拨、我的与业绩。
- 口径基线：server / web 实际实现；枚举、字段、校验、规则与 Web 同源。
- 明确不做：冲正/废除、盘点、期初导入、退卡、催收登记、报表、客户档案编辑、打印/小票等（走 Web）。
- 设计规范（可直接抽 token）：
  - 字号/行高/字重：标题 16/24 600；列表主标识 15/22 600；数值 15/22 600；时间/文本值 13/18 500；字段名/说明 13/18 400；元数据 12/16 400；徽标 12/16 500；按钮 13/18 500；页面大数字 24/32（业绩 32/40）。
  - 间距：列表行上下 padding 10、行间 1px；卡片 padding 16、内部 8、卡片间 12；页面内容 16。
  - 控件：按钮 36、筛选器 30、输入 36。
  - 圆角：卡片 12、按钮/输入 6、徽标 4。
  - 配色仅给语义：主色/次级灰/语义色；欠款红；工作台分组 客户=蓝、库存=橙、常用=中性；**具体色值未给**。
- 全局交互：四种“没内容”（数据为空/筛选无结果/条件开关无结果/加载失败）、骨架屏、失败重试、提交防重、权限、未保存离开确认、分页。
- 内容示例：张女士/李女士、小气泡/补水/肩颈、医用面膜/玻尿酸原液、金额等，可直接作为高保真内容基础。

## 3. 缺口与风险

### 3.1 架构缺口（P0）

- **缺 `b-mobile` profile/catalog。** 现有 `b-dense` 是 Web（PageShell），没有 `MobileShell`；`c-expressive` 是移动 C 端。PRD 是移动 B 端，直接用 `b-dense` 会编译失败，用 `c-expressive` 风格不对。
- **缺移动 B 端 archetype/组件**：TabBar、TopBar（微信胶囊安全区）、首页卡片、列表卡（四行/两行/资料卡）、数值块、徽标、底部动作栏、收起式筛选器、搜索、开关、步骤流程、签名/拍照/日历（后两者可后置）。
- **`b-mobile` 不是新品牌系统**，而是 b-dense 语义 + 移动布局/组件；可共享颜色/字阶，新增移动组件/archetype。

### 3.2 视觉缺口（P0/P1）

| 缺口 | 影响 | 建议 |
|---|---|---|
| 颜色 hex 未给 | 无法做品牌级高保真；只能先做中性基线 | 提供 Web token/品牌色；没有则用 b-mobile 中性基线并标 `baseline` |
| 字体家族/字重未给 | 字号有，但字体不确定 | 默认 Noto Sans SC/PingFang SC；确认 |
| 图标风格为“面性（实心）” | Lucide 主要是线性，直接套会风格不符 | 标准图标改用 Material Symbols Filled / Phosphor Fill；自定义图标走 AI 矢量草稿 |
| 组件视觉未定 | 卡片/列表/筛选/徽标的颜色、描边、阴影需定义 | 在 `b-mobile` profile 中定义并让用户审 |
| 动效未定 | 高保真原型需要转场/反馈 | 用标准预设库（已确认） |
| 视口未定 | 375×812 vs 390×844 | 建议 390×844（与现有 c-expressive 一致）；确认 |
| 插画/空态资产 | 空态需要图形 | 先中性占位/简单线性插画；缺资产标 unresolved |

### 3.3 PRD 未定项（与首版切片相关的）

- 客户手机号口径冲突（§0.4 vs 《02-客户》§3.1）——**必须定**。
- 预约来源默认值未定；就地快速建档未定（预约模块，首版切片不涉及）。
- 开单：续期做不做、抹零、实收口径、还款详情动作、是否加“只看我开的”（首版切片不涉及）。
- 库存：调拨单位口径、停用产品灰标、结存总账、部分命名收口（库存查询核心列表已定，可避开待定项）。
- 调拨：数量单位（唯一待定，首版不涉及）。
- 我的：手机号是否打码、是否放隐私政策（首版切片不涉及）。

### 3.4 内容缺口

- 列表行数：PRD 示例是 4–5 条；高保真列表需要 5–10 条，可基于示例生成合成数据。
- 真实业务数据：客户名/项目/产品/金额/库存数量已有示例结构；需要用户确认业务词表和敏感数据边界（只用合成数据）。
- 角色场景：PRD 按人勾选功能；原型需要至少一个角色视角（店长/美容师/前台），或提供角色切换。首版建议“店长（全功能）”视角，后续加切换。

## 4. 推荐首版切片

### 切片 A（推荐第一刀）：`今日` + `库存查询`

- **今日（首页）**：顶栏/门店切换/消息、快捷操作卡、我的预约列表、待回访列表、TabBar；覆盖卡片、两行列表、状态徽标、空/加载/失败、权限显隐。
- **库存查询**：搜索、收起式筛选器、仅看预警开关、汇总行、资料类卡片、预警徽标、当前/可用库存数值块、空/筛选空/失败态；覆盖 §0.9 列表规范。
- 两页都不依赖开单/调拨/欠款的未定分支；内容示例充足。
- 视口：390×844（待确认）。

### 切片 B（第三页）：`客户详情`

- 头部 + 标签、四个累计值、四 Tab、卡项卡片、消费/服务记录、底部动作栏。
- 需要先解决手机号口径；其余规则基本定稿。
- 适合作为“数据密集详情页”的验证。

### 暂不进入首版

`开单`（三步 + 签字 + 收款/分摊）、`调拨`（六动作 + 单位未定）、`欠款/还款`、`我的/业绩`、`预约日历`。这些 pages 的未定项和复杂交互会放大风险；等 `b-mobile` 稳定后再做。

## 5. `b-mobile` profile 建议

- **定位**：btokens + 移动 B 端布局/组件；不是新品牌。
- **Tokens**：直接采用 PRD §0.9 的字号/行高/字重/间距/圆角/控件高；颜色补一套中性 B 端语义色（primary/text/secondary/border/surface/success/warning/danger/info），品牌色后接。
- **Components**：TopBar、TabBar、SectionHeader、Card、ListRow（四行/两行/资料卡）、Badge、NumericBlock、BottomActionBar、SearchBar、CollapsedFilter、Switch、Tabs、EmptyState、Skeleton、ErrorState、Button、Input/Select/FormField；签名/拍照/日历后置。
- **Archetypes**：`home`（移动工作台首页）、`list`（移动列表）、`detail`（移动详情+Tab）、`form`（移动表单）、`settings`（移动设置）；`auth` 复用现有。
- **图标**：标准 UI 用 Material Symbols Filled / Phosphor Fill（面性）；自定义图标 AI 矢量草稿 + 审校。
- **渲染**：RenderPlan 支持移动端 safe-area、TabBar、底部动作栏、固定底部按钮；Figma 用 Auto Layout + layoutGrow/固定底部。

## 6. 需要用户提供/确认

1. **颜色**：品牌主色/语义色 hex，或 Web 设计系统 token；没有则用中性 b-mobile 基线并标 `baseline`。
2. **字体**：Noto Sans SC / PingFang SC 是否可用；是否有指定字体。
3. **图标**：接受 Material Symbols Filled / Phosphor Fill，还是指定图标库。
4. **视口**：390×844 还是 375×812。
5. **手机号口径**：客户详情是否隐藏/脱敏（PRD 内部冲突），统一一个规则。
6. **切片确认**：首版是否就做 `今日` + `库存查询`；`客户详情` 第三页。
7. **内容**：是否直接用 PRD 示例内容 + 合成数据；业务词表/敏感字段边界。
8. **项目性质**：这是测试 PRD（验证管线）还是真实产品（需要品牌级交付）；决定是否现在接真实品牌资产。

## 7. 下一步（确认后）

1. 建 `b-mobile` profile/catalog（tokens + 移动组件/archetype）。
2. 从 PRD 抽取 `今日` + `库存查询` 的 UI Brief（含 content/state/roles/actions）。
3. 生成 RenderPlan，做 HTML 两页垂直切片 + 截图。
4. 用户看实物后，再决定铺更多页面、接 Figma、做海报。
